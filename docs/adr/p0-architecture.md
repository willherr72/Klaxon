## P0-03 native session candidate

The [approved P0-03 backlog](../../KLAXON_V2_DESIGN_AND_IMPLEMENTATION_PLAN.md#9-implementation-backlog) calls for login, refresh and logout on both native targets. Before wiring a WebView to Convex, test whether a new native process can recover an owner-bound refresh marker and still require provider confirmation before granting access. The Windows candidate uses current-user DPAPI. The Android candidate uses an app-owned Android Keystore key to protect a record in private storage. Access tokens stay in memory. Both routes use OS facilities within the $0 additional budget. [Microsoft ProtectedData](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.protecteddata) · [Android Keystore](https://developer.android.com/privacy-and-security/keystore)

Use only inert synthetic markers, a temporary store, two fixture owners and a simulated refresh response. Successful refresh may rotate the marker. A transport failure grants no access and permits retry. Expiry clears the record. Logout must survive relaunch, and one owner must never resume from the other owner's record. Keep marker values out of output and plaintext files. Record OS protection, cold-process behavior and provider simulation separately. The portable account client continues to require sign-in on reload.

The offline synthetic package uses separate session commands. The hosted provider package pins its origin and uses native sign-in and refresh before giving the SDK an access token. The portable account client keeps both tokens in memory and requires sign-in on reload. [Account client](../../spikes/p0/portable/account.js) · [Hosted packager](../../spikes/p0/native/README.md#hosted-packaged-native-acceptance)

The Windows experiment exercises the option in which native code owns authenticated reads and subscriptions. The WebView receives projected task IDs and titles over Tauri IPC. Native drops the active subscription on sign-out, and the WebView discards replies that were already in transit when the session changed. A Windows process hosting a simulated provider exercises this boundary with no network or added service. [Packaged test and limits](../klaxon-v2-progress.md#packaged-windows-authenticated-task-read-and-subscription)

Use the Convex SDK with short-lived access tokens in WebView memory for the spike. Keep refresh credentials in native storage. Keeping both tokens native would require rebuilding authenticated subscriptions and reconnect. Packaged Windows and the Android emulator passed cold resume, refresh rotation and exact-session revocation against the disposable hosted deployment. Production adoption still requires a secure-storage review on the intended Android device. [Hosted acceptance](../klaxon-v2-progress.md#hosted-packaged-native-acceptance) · [Security](../security.md)

The simulated provider can retire an access value immediately to check whether the SDK switches both its HTTP client and subscription. The pinned provider returns a replacement **refresh token** on a successful exchange. Native code must durably store that replacement before reporting success to the WebView. On a real local provider, revoking the packaged Windows session invalidated its cached bearer for reads and emptied its uninterrupted subscription while another login for the same owner stayed usable. During a subscription outage, the previously rendered task stayed visible until the same client reconnected and received an empty update. Treat cached reads as stale while disconnected, as the plan requires. Android also passed the [local reconnect test](../klaxon-v2-progress.md#android-subscription-reconnect-after-revocation). The [hosted packaged checks](../klaxon-v2-progress.md#hosted-packaged-native-acceptance) observed the same access denial on both platforms. The same reconnect check passed on [physical Android](../klaxon-v2-progress.md#physical-android-hosted-session). [Reconnect evidence](../klaxon-v2-progress.md#windows-subscription-reconnect-after-revocation) [Windows provider evidence](../klaxon-v2-progress.md#packaged-windows-revocation-on-a-real-local-provider) [Account client](../../spikes/p0/portable/account.js) · [Offline SDK comparison](../klaxon-v2-progress.md#offline-convex-sdk-owner-switch)

Convex Auth 2.1.0 lets a client retry the presented refresh token until its successor is first used. The native client therefore needs a single writer per session. Before publishing a replacement it must keep the preceding record recoverable. After publication a new process must recover the successor, even if the WebView never received an acknowledgment. A valid `noSession` response ends the session. A malformed response or transport failure must preserve the protected record for retry. The packaged fixture can test these storage boundaries using synthetic responses. Hosted acceptance must separately check the real provider’s retry and revocation behavior. [Pinned package](../../spikes/p0/package.json) · [Windows fixture procedure](../../spikes/p0/native/README.md#packaged-windows-sdk-handoff)

The Android fixture uses a single packaged app process, serialized plugin calls, a non-exportable Keystore key and an encrypted `AtomicFile` in app-private storage. Android can log a failed rename and return from `finishWrite`. The client therefore compares the published ciphertext with the staged bytes before issuing access. A new process still has to obtain provider confirmation. [Android fixture procedure](../../spikes/p0/native/README.md#packaged-android-sdk-handoff)

On Android, initial sign-in can die after key creation but before the encrypted record is published. Under the fixture's single-writer assumption, resume or a fresh validated sign-in may discard that slot's staging file and key only when both the published record and its legacy backup are verifiably absent. A backup blocks cleanup even when the base file is missing. The [initial sign-in evidence](../klaxon-v2-progress.md#android-initial-sign-in-to-keystore) covers these two recovery paths.

The [Windows](../klaxon-v2-progress.md#windows-sign-out-after-a-lost-acknowledgment) and [Android](../klaxon-v2-progress.md#android-sign-out-after-a-lost-acknowledgment) fixtures distinguish an issuer that may have committed revocation from a client that received confirmation. Keep the protected refresh record available for an idempotent retry while denying fresh access. Persist a confirmed acknowledgment before deleting that record so local cleanup can resume after process termination. Both fixtures validate the same Convex response in Rust. A separately built Windows fixture sends the native sign-out mutation over IPv4 loopback. Once it records the pending journal it can release the in-memory provider mutex, so concurrent SDK access sees the revoked owner while the file lock still protects the ciphertext. [Packaged HTTP evidence](../klaxon-v2-progress.md#packaged-windows-sign-out-over-loopback-http)

The opt-in Windows build also exercises cold refresh over native HTTP. The fixture gives transport status precedence over the body, commits a valid successor to DPAPI before granting access, and requires confirmed expiry before clearing the slot. The sealed Windows record binds each grant to a session identifier that survives rotation and changes at fresh sign-in. A surviving native provider checks that identifier on its next access. [Cold refresh evidence](../klaxon-v2-progress.md#packaged-windows-cold-refresh-over-loopback-http) · [Replacement evidence](../klaxon-v2-progress.md#windows-session-replacement-for-the-same-owner)

## Shared client and backend

Accepted for the spike on 2026-11-23. Retain the existing shared static Svelte/Vite build. Keep native OS services behind Tauri commands. Place the spike in its own package so its dependency graph and generated configuration cannot enter a v1 release. Use a mount-relative task fragment (`#/tasks/<encoded-id>`) as the P1 routing candidate. The static host can serve the entry document on direct navigation and reload without a rewrite. Windows Tauri also served a history-style path through its asset fallback. P1 still needs to resolve the ID within the active account and open the task detail. [Routing probe](../klaxon-v2-progress.md#task-links-on-static-and-tauri-origins)

Convex owns online state. An owner-indexed subscription to a bounded task list is the first slice. Resolve the owner from the verified session inside each backend function. Retain Convex Auth for the spike after hosted login, refresh, logout and realtime checks in the portable client, Windows WebView2 and emulator Android WebView. The isolated Android emulator denied a cold resume while its only provider route was absent, preserved the sealed record, and recovered after the route returned. A hosted internet outage on a physical device still requires testing. [Hosted portable and physical sync](../klaxon-v2-progress.md#remaining-p0-tests) · [Hosted native sessions](../klaxon-v2-progress.md#hosted-packaged-native-acceptance) · [Emulator route-loss evidence](../klaxon-v2-progress.md#android-emulator-loss-of-its-provider-route)

Keep deterministic integration reconciliation and reminder scheduling in the backend. Give agents scoped, versioned HTTP/MCP access to the same validated domain functions. Select native vs web notification delivery from actual background and closed-app evidence. A provider acknowledgement alone cannot establish that a person received a reminder.

Keep portable account rows and their timestamp visible during reconnect. The browser marks them stale and holds writes until data from the current connection arrives. A pending HTTP read cannot advance freshness after the connection that started it is lost. [Portable browser regression](../klaxon-v2-progress.md#portable-account-task-freshness)

Will's [owner-reported physical smoke](../klaxon-v2-progress.md#remaining-p0-tests) supports keeping Convex for the hosted task spike. Android saved a rename while Windows was powered off, and Windows read it back after restart. Android signed in again after reopening. The subsequent physical phone run verified protected cold resume and logout. The reminder decision and delivery limits are recorded above.

Keep v1 authoritative during rehearsal. Use synthetic archives and a disposable workspace. Cross-device reconciliation, restore and explicit owner acceptance precede a change of authority. Running both schedulers on real data would make delivery results ambiguous.

The loopback probe permits synthetic password registration and keeps tokens in memory. Before a hosted test, restrict enrollment to disposable test identities, use HTTPS and confirm the team is Free. The P1 auth decision depends on reload, expiry, concurrent refresh and revocation in actual clients. Keeping the same UI code does not make browser storage or native callbacks equivalent.
