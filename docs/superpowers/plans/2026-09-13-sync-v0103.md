# Sync v0.10.3 Implementation Plan

> **For agentic workers:** Use test-driven development for implementation and independent review before release.

**Goal:** Reliable revision-based sync, Android recovery, explicit compatibility, and a published v0.10.3 release.

**Architecture:** A local revision journal supplies stable snapshots; shared transactional storage applies them. A versioned Iroh session carries the pass and a single coordinator controls outgoing work.

**Tech Stack:** Rust, SQLite/rusqlite, Iroh 1.0.3, Tauri, Kotlin, Svelte.

**Spec:** `docs/superpowers/specs/2026-09-13-sync-v0103-design.md`

## Global constraints

- Preserve existing user data, pairing secrets, and endpoint identity.
- Version all shippable manifests `0.10.3`; publish both signed platform artifacts.
- Legacy peers receive update errors and cannot advance revision cursors.
- Keep conflict timestamps separate from delivery revisions; acknowledge only committed batches.

## Task 1: Durable revision storage

- [x] Add failing migration/revision and rollback tests in `db/sync_log.rs` and `sync/storage.rs`; run `cargo test --offline --lib sync_log` and storage tests.
- [x] Add migration 016, triggers, epoch, per-peer cursors, seeded journal, revision snapshots, transactional application, and idempotent tombstones.
- [x] Expose `Cursor { epoch: String, revision: i64 }`, `Batch { cursor: Cursor, changes: ChangeSet }`, `snapshot(conn, Option<&Cursor>)`, `cursors(conn, peer)`, `mark_pushed(conn, peer, cursor)` in `db::sync_log`; expose transactional `apply` and `apply_pulled` plus committed effects in `sync::storage`.
- [x] Verify late A-to-B-to-C imports with nonzero cursors, concurrent edits after snapshot, equal clock values, epoch replacement, and injected write failures through production functions.
