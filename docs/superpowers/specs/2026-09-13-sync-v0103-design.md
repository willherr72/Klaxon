# Sync v0.10.3 design

Approved scope: all five recommendations in `docs/2026-09-13-iroh-sync-review.md`, followed by a signed Android and Windows GitHub release.

Use a SQLite revision journal maintained by triggers for every synced entity. Revisions describe local availability, including imported changes, independently of conflict timestamps. Store the latest revision per entity with an AUTOINCREMENT sequence and a persistent database epoch. Seed existing rows during migration; new per-peer revision cursors start empty and cause full reconciliation. A mismatched epoch or cursor beyond the journal triggers full reconciliation. Explicit backup restore rotates the staged database epoch before replacing live files. Receiving a new or regressed peer history invalidates outbound cursors in the same transaction, so failed sends retry a full snapshot. Keep legacy timestamp columns for diagnostics only.

Read a revision-bounded snapshot in one SQLite transaction. Advance delivery only to the snapshot cursor after acknowledgment; concurrently edited rows receive later revisions. Apply received batches and pull cursors transactionally through a shared storage function. Real errors roll back; unchanged conflicts are accepted idempotently. Publish effects after commit and record sync success only once the complete pass succeeds.

Introduce ALPN `klaxon/sync/1` and explicit protocol version 1. Keep a legacy handler for Hello/Ping and actionable update errors, with no legacy data mutation. Append new request/response variants rather than changing historical layouts. A new client verifies the negotiated protocol before any data request. Reuse one connection per pass with bounded request and connection deadlines. A legacy Hello probe distinguishes an old reachable peer from a transport outage.

Route foreground/manual triggers through the scheduler; serialize warm-worker and scheduled passes. Notify Iroh on Android resume and connectivity changes. Permit bounded, cooldown-protected endpoint health recovery while foreground only, preserving the existing identity and pairing records. A sleeping peer alone must not trigger endpoint rebuilds.

Regression tests cover migration with existing data/pairings, late imported edits, in-flight edits, clock skew/rollback, equal timestamps for distinct edits, transaction failure/retry, epochs, supported/mixed protocols, malformed frames, and serialized scheduling. Add real transport exercise in a runnable integration harness. Existing last-write-wins conflict policy remains; delivery revisions do not claim to merge competing edits automatically.

Release versions must all be `0.10.3`; preserve data/pairings and signing identity. Publish `Klaxon_0.10.3_x64-setup.exe` and `klaxon-0.10.3-arm64.apk` together after verification.
